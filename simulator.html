The attitude-control simulator

Set an upset, choose a controller and watch the closed loop work: the safe-mode logic detumbles the spacecraft, holds it, then hands it back to precise pointing. Every run is checked against the project’s five requirements.

What one run computes

A run is a loop over time steps of \(\Delta t = 0.01\) s Site default: 12,001 samples for 120 s. Each step does the same six things, in this order. The engine works in SI units (rad, rad/s, N m); the page converts to degrees, deg/s and mN m only for display.

1. Measure the error

The attitude \(q\) is a unit quaternion, scalar first, that rotates body vectors into the inertial frame. The error relative to the target \(q_{ref}\) is another quaternion, and its angle is computed with atan2, which stays accurate at tiny angles where acos loses precision:

\[ q_e = q_{ref}^{*}\otimes q \;(\text{negated if } q_{e0}<0), \qquad \theta = 2\,\operatorname{atan2}\!\bigl(\lVert q_{e,v}\rVert,\; q_{e0}\bigr) \]

Worked number: the T01 start (roll 25°, pitch −15°, yaw 20°, applied yaw first) is the quaternion …, which is … from the target Derived. That angle is the “from target” readout under the attitude sliders.

2. Run the mode logic

The mode manager compares the rate \(\lVert\omega\rVert\), the error \(\theta\) and the fault flag with the project’s thresholds Project. All timers count whole steps, so “0.5 s” is exactly 50 steps at \(\Delta t = 0.01\) s:

\[ \begin{aligned} \text{NOMINAL}\to\text{SAFE\_DETUMBLE}&: \ \lVert\omega\rVert > 6^\circ/\text{s} \ \text{ or fault for } 0.5\ \text{s} \\ \text{SAFE\_DETUMBLE}\to\text{SAFE\_HOLD}&: \ \lVert\omega\rVert < 0.5^\circ/\text{s} \ \text{held for } 2\ \text{s} \\ \text{SAFE\_HOLD}\to\text{NOMINAL}&: \ \text{fault clear},\ \lVert\omega\rVert<0.5^\circ/\text{s}, \\ &\phantom{:}\ \ \theta<4^\circ,\ \text{dwell}\ge 8\ \text{s} \end{aligned} \]

There is deliberately no path from SAFE_DETUMBLE straight back to NOMINAL, and none from NOMINAL straight to SAFE_HOLD. The annunciator above shows the guard lamps for whichever mode the cursor is in.

3. Compute the torque the mode asks for

NOMINAL uses the selected controller; SAFE_DETUMBLE only damps the rate; SAFE_HOLD points gently with low gains:

\[ \begin{aligned} \tau_{PID} &= -K_p\,q_{e,v} - K_d\,\omega - K_i\!\int q_{e,v}\,dt, & \tau_{LQR} &= -K\begin{bmatrix}2q_{e,v}\\ \omega\end{bmatrix}, \\ \tau_{SD} &= -K_{d}^{SD}\,\omega, & \tau_{SH} &= -K_{p}^{SH} q_{e,v} - K_{d}^{SH}\,\omega \end{aligned} \]

The units follow from the inputs: \(q_{e,v}\) is dimensionless, so \(K_p\) is in N m, \(K_d\) in N m s/rad and \(K_i\) in N m/s. For small errors \(q_{e,v}\approx\theta/2\), so the PID behaves like a spring of stiffness \(K_p/2\) per radian. On the y axis (\(J_y = 0.040\ \text{kg m}^2\)) with the site gains that gives

\[ \omega_n = \sqrt{\frac{K_p/2}{J_y}}, \qquad \zeta = \frac{K_d}{2\sqrt{(K_p/2)\,J_y}} \]

so the PID is heavily overdamped, which is why T01 settles smoothly but slowly Derived. The LQR gains come from the project’s weights \(Q = \operatorname{diag}(2,2,2,0.15,0.15,0.15)\) and \(R = 2000\,I\) Project, which give \(K_\theta = \sqrt{q_\theta/r}\) = … N m/rad on every axis Derived.

4. Limit the torque to what the wheels can give

\[ \tau_i = \min\bigl(\max(\tau_{cmd,i},\,-\tau_{max}),\ \tau_{max}\bigr), \qquad \tau_{max} = 3\ \text{mN m} \]

Worked number: at the T01 start the PID demands \(-K_p\,q_{e,v} = \) … mN m, so the x and z wheels saturate for the first moments. The REQ-S2 badge reports both the delivered peak (3.00 mN m) and the demand. With the LQR, the attitude term alone reaches the limit at \(\theta = \tau_{max}/K_\theta = \) … Derived, so a 37° slew runs at full torque and builds up rate.

5. Advance the physics one step

The torque is held constant over the step (zero-order hold, as a flight computer would apply it) and the rigid-body equations are integrated with fourth-order Runge–Kutta, then \(q\) is renormalised Project:

\[ J\dot\omega + \omega\times(J\omega) = \tau + \tau_d, \qquad \dot q = \tfrac12\, q\otimes\begin{bmatrix}0\\ \omega\end{bmatrix} \]

with \(J = \operatorname{diag}(0.035,\ 0.040,\ 0.025)\ \text{kg m}^2\) Project, diagonal because the body axes are principal axes.

The term \(\omega\times(J\omega)\) couples the axes: it is why a spin about the intermediate axis x is unstable (try SPINX). It moves rate from one axis to another but does no work, because \(\omega\cdot(\omega\times J\omega)=0\). The rotational kinetic energy \(T=\tfrac12\,\omega^{\mathsf T}J\omega\) therefore changes only through the applied torques, \(\dot T=\omega\cdot(\tau+\tau_d)\), so the detumble law \(\tau=-K_d\,\omega\) removes energy at the rate \(K_d\lVert\omega\rVert^2\) whatever the coupling does. While a wheel is clipped at 3 mN m, each product \(\omega_i\tau_i\) is still negative, so the energy keeps falling, only more slowly. Worked number: T03 starts with \(T = \) …, and safe mode removes more than 99% of it in the first 2 s Derived.

The disturbance \(\tau_d = [2,\,-1,\,1.5]\times10^{-5}\) N m Project is about 150 times smaller than \(\tau_{max}\), so it only shows near the target, where the PID’s integral term cancels it.

6. Log the step, then check the requirements

Every step is logged: time, \(q\), \(\omega\), commanded and delivered torque, errors, mode, fault flag and the three timers. After the run, the requirement checks read only the log. Settling time is the first time after which the error stays below 2° and the rate below 0.5 deg/s to the end; the effort is \(\int \lVert\tau\rVert^2\,dt\) by the trapezoid rule, in N² m² s. The plots, the 3D view and the CSV are all views of that same log.

Where the numbers come from

The original project shipped an interactive interface that set the initial roll, pitch and yaw, the initial body rates, the controller (PID or LQR), the duration, safe mode, a fault window and the playback speed, then ran the simulation, played a 3D animation and saved a CSV Project. This page rebuilds that interface, adds the gains, the disturbance, the actuator and integrator options, and brings the project’s Monte Carlo campaign into the same page. The sensor and estimator model goes beyond what the project had Extension.
