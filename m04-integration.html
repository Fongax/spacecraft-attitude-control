MODULE 04

Numerical integration

Advance the attitude state in time without letting the numbers drift: RK4, renormalisation, step size and floating point.

Phase: Model About 25 min

    The state and its ODE

    A simulator never solves the equations of motion exactly. It advances the state in fixed steps of length \(h\), and every step replaces the true curve with an approximation. This module is about choosing that approximation so that its errors stay far below anything the requirements care about, and about the few places where the arithmetic itself can bite.

    The project packed everything that changes with time into one state vector of 10 numbers Project: the attitude quaternion \(q\) (4 numbers, dimensionless), the body rate \(\omega\) (3, in rad/s) and the running integral of the attitude error used by the PID controller (3). Its time derivative depends only on the state and the torque:

    \[ x=\begin{bmatrix} q\\ \omega \\ \int q_{e,v}\,dt\end{bmatrix},\qquad \dot x=f(x,\tau)=\begin{bmatrix}\tfrac12\,\Omega(\omega)\,q\\[3pt] J^{-1}\big(\tau+\tau_d-\omega\times J\omega\big)\\[3pt] q_{e,v}\end{bmatrix} \]

    The first block is the quaternion kinematics and the second is Euler's equation from module 03, with \(J=\operatorname{diag}(0.035,\,0.040,\,0.025)\) kg m² Project, the control torque \(\tau\) and the disturbance \(\tau_d\) in N m. \(\Omega(\omega)\) is the 4 × 4 rate matrix:

    \[ \Omega(\omega)=\begin{bmatrix}0&-\omega_x&-\omega_y&-\omega_z\\ \omega_x&0&\omega_z&-\omega_y\\ \omega_y&-\omega_z&0&\omega_x\\ \omega_z&\omega_y&-\omega_x&0\end{bmatrix} \]

    Check the units row by row: \(\dot q\) is in 1/s because \(\omega\) is in rad/s, and \(\dot\omega\) is in rad/s² because N m divided by kg m² is 1/s². An equation whose rows do not balance like this is wrong before you run it.

    Two modelling choices shape the rest of the module. First, the torque is held constant across each step (a zero-order hold), because the controller computes one new command per step of dt = 0.01 s Site default. Second, this site keeps the integral as a controller state that is updated once per step, the way flight code would hold it, instead of inside the integrated vector Site default. The difference in the results is negligible, and the integrator then works on a 7-number state \(x=[q,\ \omega]\).

    Forward Euler

    The simplest scheme, forward Euler, follows the slope at the start of the step in a straight line:

    \[ x_{n+1}=x_n+h\,f(x_n) \]

    It is easy to write and it is first order: halving \(h\) roughly halves the error. On the quaternion kinematics, though, it has a flaw you can prove in two lines. One Euler step multiplies \(q\) by the matrix \(I+\tfrac h2\Omega\). Because \(\Omega\) is skew-symmetric (\(\Omega^\mathsf{T}=-\Omega\)) and \(\Omega^\mathsf{T}\Omega=\lVert\omega\rVert^2 I\), the cross terms cancel and

    \[ \lVert q_{n+1}\rVert^2=q_n^\mathsf{T}\big(I+\tfrac h2\Omega\big)^{\mathsf T}\big(I+\tfrac h2\Omega\big)\,q_n=\Big(1+\frac{h^2\lVert\omega\rVert^2}{4}\Big)\lVert q_n\rVert^2 \]

    The factor is larger than 1 for any non-zero rate, so the quaternion grows on every step and never shrinks. The growth compounds: at \(\omega=(5,\,-3,\,4)\) deg/s and \(h=0.1\) s, \(|q|\) reaches 1.0192 after 100 s Derived. A quaternion that is not unit length is no longer a pure rotation. It stretches every vector it rotates and corrupts the error angle that the controller and the safe-mode logic read.

    You may have met Euler time stepping as a first numerical-methods exercise: hand-coded Euler and Runge–Kutta loops are typical content of an introductory programming subject for engineers Typical content. The same rectangle rule hides inside a digital PID, whose integral term is the running sum \(\sum e\,\Delta t\). And a residual block \(x+F(x)\) in a deep network has exactly the shape of one explicit Euler step, with depth playing the role of time Analogy.

    RK4 and Simpson

    The classical fourth-order Runge–Kutta method, RK4, is what the project used Project. It samples the slope four times per step, twice at the midpoint, and blends the samples with weights 1-2-2-1:

    \[ \begin{aligned} k_1&=f(x_n), & k_2&=f\big(x_n+\tfrac h2 k_1\big),\\ k_3&=f\big(x_n+\tfrac h2 k_2\big), & k_4&=f\big(x_n+h\,k_3\big),\end{aligned}\qquad x_{n+1}=x_n+\tfrac h6\big(k_1+2k_2+2k_3+k_4\big) \]

    Why those weights? If \(f\) depends only on time, then \(k_2=k_3=f(t_n+\tfrac h2)\) and the update collapses to

    \[ x_{n+1}=x_n+\frac h6\Big[f(t_n)+4f\big(t_n+\tfrac h2\big)+f(t_n+h)\Big] \]

    which is Simpson's rule for \(\int f\,dt\) over the step. Numerical quadrature with the trapezoid and Simpson rules is typical content of an engineering mathematics subject Typical content. This site uses the trapezoid rule, Simpson's lower-order cousin, to turn logged torque into the control-effort metric.

    The deeper reason is Taylor series. The four stages are arranged so that the Taylor expansion of the update matches the true solution up to the \(h^4\) term; the first mismatch is in \(h^5\). So the local error made in one step is \(O(h^5)\). Over a fixed duration \(T\) there are \(T/h\) steps, and the local errors add up to a global error of \(O(h^4)\). Taylor series with remainder are typical content of a second calculus subject Typical content.

    In code, a step is a small, single-purpose function that takes the dynamics as an argument, so the same stepper can serve the attitude model, a wheel model or an estimator:

    function rk4Step(f, x, h) {
  const k1 = f(x);
  const k2 = f(axpy(x, h / 2, k1));   // axpy(x, a, k) = x + a·k
  const k3 = f(axpy(x, h / 2, k2));
  const k4 = f(axpy(x, h, k3));
  return x.map((xi, i) => xi + h / 6 * (k1[i] + 2 * k2[i] + 2 * k3[i] + k4[i]));
}

    RK4 costs four evaluations of \(f\) per step against Euler's one. That is a bargain: at \(h=0.1\) s the RK4 norm error after 100 s is about \(-3.8\times10^{-13}\) Derived, while Euler's is \(1.9\times10^{-2}\) Derived. Getting Euler that close would take a step tens of billions of times smaller.

    Why |q| drifts and renormalisation

    The exact solution keeps \(|q|=1\) for ever. Differentiate the squared norm along the true flow:

    \[ \frac{d}{dt}\lVert q\rVert^2=2\,q^\mathsf{T}\dot q=q^\mathsf{T}\Omega(\omega)\,q=0 \]

    The last step holds because the quadratic form of a skew-symmetric matrix is zero: \(q^\mathsf{T}\Omega q\) equals its own transpose \(q^\mathsf{T}\Omega^\mathsf{T}q=-q^\mathsf{T}\Omega q\). Matrices, transposes and this kind of argument are typical content of a first engineering mathematics subject Typical content. Geometrically, a unit quaternion lives on the unit sphere in four dimensions and the true motion slides along that sphere.

    Discrete steps leave the sphere. Euler always steps outward, by the factor above. RK4 steps very slightly inward, because its update truncates the exponential series after the fourth power: after 100 s at \(h=0.1\) s the RK4 drift is \(-3.8\times10^{-13}\) Derived, ten orders of magnitude below Euler's. For a constant rate there is also an exact one-step solution, the matrix exponential, which the widget below uses as ground truth:

    \[ q(t+h)=\Big[\cos\big(\tfrac{|\omega|h}{2}\big)\,I+\frac{\sin\big(|\omega|h/2\big)}{|\omega|}\,\Omega(\omega)\Big]\,q(t) \]

    It follows from \(\Omega^2=-|\omega|^2 I\): the power series of \(e^{\Omega h/2}\) splits into a cosine series and a sine series.

    The project renormalises after every RK4 step, \(q\leftarrow q/|q|\) Project. It is cheap and it ends the norm drift, but notice what it is: a projection back onto the sphere, not a correction. It fixes the length and leaves any error in the direction alone. In the widget, toggle renormalisation and watch \(|q|\) change while the attitude error against the exact solution does not. Strapdown inertial navigation does the same thing with real gyro data, integrating \(\dot q=\tfrac12\Omega(\omega)q\) and renormalising, which is typical content of a navigational-systems subject Typical content.

    Order of accuracy

    A method of order \(p\) has a global error of about \(C\,h^p\) once \(h\) is small. Halving the step therefore divides the error by \(2^p\), and the ratio of successive errors measures \(p\) directly:

    \[ \frac{e(h)}{e(h/2)}\approx 2^p\qquad\Longrightarrow\qquad p\approx\log_2\frac{e(h)}{e(h/2)} \]

    Expect a ratio of about 2 for Euler (\(p=1\)), about 4 for the midpoint method RK2 (\(p=2\)) and about 16 for RK4 (\(p=4\)). The errors are measured against a reference run of RK4 with a step 64 times smaller, whose own error is far below everything being compared.

    This is the same doubling-ratio test the Algorithms notes use on running times: double \(n\) and a ×4 in time means \(O(n^2)\). Here it is the best unit test an integrator can have. A typo in one RK4 stage still produces smooth, believable trajectories, and only the ratio gives it away. The test problem below is torque-free rotation, \(J\dot\omega=-\omega\times J\omega\), which conserves kinetic energy and the angular-momentum magnitude exactly. Conservation of both in torque-free motion is typical content of a physics subject that covers rotation and angular momentum Typical content, so their drift is a second accuracy check.

    Step size and stability

    Accuracy asks whether errors are small; stability asks whether they stay small instead of growing step after step. The standard test linearises the dynamics around the motion of interest and applies the method to \(\dot\omega=\lambda\omega\). Every step then multiplies \(\omega\) by an amplification factor \(R(z)\) that depends only on \(z=h\lambda\):

    \[ R_\text{Euler}(z)=1+z,\qquad R_\text{RK4}(z)=1+z+\frac{z^2}{2}+\frac{z^3}{6}+\frac{z^4}{24} \]

    The numerical solution decays only if \(|R(z)|\le 1\). On the negative real axis Euler is stable for \(-2\le z\le 0\), that is \(h\le 2/|\lambda|\); RK4 is stable out to \(z\approx-2.785\). Notice that RK4's factor is the Taylor series of \(e^z\) cut off after \(z^4\), the same truncation that made the quaternion shrink slightly in the last section.

    Detumble supplies a concrete \(\lambda\). The law \(\tau=-K_d\,\omega\) turns each axis into \(\dot\omega=-(K_d/J)\,\omega\), so on the z axis \(\lambda=-0.05/0.025=-2\) s⁻¹, with \(K_d\) a Site default and \(J_z\) from the project. The critical step is 1 s for Euler and 1.39 s for RK4 Derived, a hundred times larger than dt = 0.01 s. The simulator is nowhere near its stability limit: the step is set by the control period, not by the integrator.

    The same arithmetic runs machine learning. Gradient descent \(\theta\leftarrow\theta-\eta\nabla L\) is forward Euler on the gradient flow \(\dot\theta=-\nabla L\), and on a quadratic with curvature \(\lambda\) the learning rate must satisfy \(\eta<2/\lambda\), the Euler limit again Analogy. The Intelligent Systems notes record what happens just past that limit: a learning rate only 5% too large diverged within 10 epochs.

    Floating point and timers

    Even a perfect method runs on imperfect numbers. IEEE 754 doubles (float64) carry about 15 significant digits and singles (float32) about 7; the machine epsilon, the gap between 1 and the next representable number, is \(2.2\times10^{-16}\) and \(1.2\times10^{-7}\). The Data Structures notes cover exactly this representation, and number formats (two's complement, fixed point, IEEE 754) are typical content of a computer-architecture subject Typical content. Flight processors often compute in float32, so three traps matter.

    Error angles. For a small error, \(q_0=\cos(\theta/2)\approx1-\theta^2/8\) sits just below 1. Once \(\theta^2/8\) is smaller than half the gap below 1, \(q_0\) rounds to exactly 1 and \(2\arccos(q_0)\) returns zero: in float32 this happens below about \(4.9\times10^{-4}\) rad, about 0.03° Derived. Just above the threshold the answer comes in coarse steps. The form \(2\,\operatorname{atan2}(\lVert q_v\rVert,\,q_0)\) reads the small part \(\lVert q_v\rVert\approx\theta/2\) directly and stays accurate to the last digit, which is why the site, like the project, never uses acos for error angles.

    Timers. 0.01 has no exact binary form, so the stored value is a hair off and the error accumulates. Adding 0.01 800 times in float64 gives 7.99999999999987, not 8, and a loop that waits for \(t\ge 8\) needs 801 steps. A dwell timer written that way fires one step late. Counting whole steps cannot drift: this site's mode logic counts the 8 s dwell as an integer, 800 steps at dt = 0.01 s Derived.

    Comparisons. Never test floats with ==. Use a tolerance that matches the meaning of the number, such as \(\big|\,|q|-1\big|<10^{-9}\) for a renormalisation check, and compare thresholds with the strict inequality the requirement states.

    Locating a threshold crossing

    The simulator checks its thresholds once per step, so it learns that the rate crossed 0.5 deg/s somewhere inside a 0.01 s step, but not where. For a requirement such as "reach the detumble threshold within 60 s" that resolution is ample. When finer timing matters, for example in the spread of detumble times across Monte Carlo trials, the crossing can be located inside the step.

    The trick is bisection. Within one short step the predicate "\(|\omega|<0.5\) deg/s" changes value once, so it is monotone. Re-integrate from the start of the step over half the step and check which half contains the crossing; keep that half and repeat. Each halving halves the uncertainty, so after \(k\) halvings it is \(h/2^k\):

    \[ \Delta t_k=\frac{h}{2^k},\qquad \Delta t_{10}=\frac{0.01\ \text{s}}{1024}\approx 10\ \mu\text{s} \]

    Ten extra sub-steps buy a thousand-fold sharper crossing time Derived. This is binary search on a continuous variable, from the same toolbox as the Algorithms notes' search and complexity material.
